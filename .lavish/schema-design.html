Experium DB Schema — m1-foundation / Issue #16

Resolved design · ready for migration

Migration plan: DROP + recreate all tables in a single migration file. exhibits currently exists (1 test row, no RLS) — will be dropped. Migrations dir is empty; this file becomes the single source of truth.
Resolved decisions
User identity
fingerprintjs (open-source) as primary. users.fingerprint_id = TEXT UNIQUE NULL. Internal PK is UUID. All FKs use UUID.
users RLS
Anon = INSERT only. No anon SELECT/UPDATE. Reads + updates via server-side API route using service role key.
ENUM strategy
TEXT + CHECK constraints throughout. No Postgres native CREATE TYPE — easier to alter pre-launch.
Tier scale
gold | silver | bronze everywhere — on exhibits.tier and ads.tier_target. No separate A/B/C scale.
Ad tier cross-reference
ad_tier removed from exhibit_qr_codes. Ad system cross-references exhibits.tier directly via exhibit_id join.
User types
users.type = visitor | maintainer. Admins live only in Supabase Auth — no row in users table.
user_progress removed
Dropped. scans.discovered BOOLEAN replaces it. Progress = SELECT DISTINCT exhibit_id FROM scans WHERE user_id = $uid AND discovered = true.
scans mutability
Scan row updated in-place as user listens. listened, listen_duration_sec, discovered updated via service role. scanned_at = creation timestamp.
reports.reporter_type
Dropped. Derive from users.type via join. reports.user_id NOT NULL — every reporter must have a users row.
ads ownership
ads.sponsor_id UUID NOT NULL FK → ad_sponsors. Every ad owned by a sponsor — including in-house (Experium = a sponsor row). Drop advertiser TEXT.
report-photos bucket
Skip in v1. reports.photo_url column dropped entirely. Two buckets only: audio + images.
Storage paths
Relative paths stored (e.g. exhibits/uuid/en.mp3). App constructs full URL at runtime via Supabase storage client.
