Tradeoffs

Dimension Option A Thumbnail card Option B Icon button Option C Gallery slide
Discoverability High — full-width visual block, hard to miss before user taps Listen. Low — small icon; easy to miss, especially once audio is playing. Medium — discoverable only for users who scroll through photos. Audio-first visitors may never see it.
Sheet height Adds ~124px. Taller sheet on small phones. No extra height. Gallery already takes ~200px (square aspect ratio). 360° slide adds zero extra height.
Mental model Clear: 360° is a distinct feature alongside audio. Unclear: small icon next to Navigate may read as "navigate in 360°." Natural: photo gallery → one slide is a 360° panorama. Consistent with how photo apps work.
When exhibit has no tour Card not rendered — no gap. Button not rendered — row unchanged. Gallery renders without the 360° slide. Fully transparent to users.
Gallery dependency None — works with or without gallery. None — works with or without gallery. Requires exhibit to have a gallery. If no photos, 360° slide would be the only item — awkward.
Feature weight High — dedicated visual block signals "this is a feature." Low — undersells the experience. Medium — contextual but not headline-level.
Implementation New card component + slot in PreviewSheet. One extra button in existing flex row. Modify Gallery to accept an optional 360 slide; Gallery is a separate component from PreviewSheet — requires wiring tour_node_id down into it.
